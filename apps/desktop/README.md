# GitCode 桌面应用

桌面源码位于 `apps/desktop`。以下开发命令可在仓库根目录执行；直接运行 `node scripts/...` 或定位源码时，请先进入 `apps/desktop`。依赖统一在仓库根安装，使用唯一的根 `bun.lock`。

面向 Windows、macOS 开发者的本地 Git 工作台。当前技术体系为 **Electron + Vue 3 + TypeScript + Pinia + Node.js + Git CLI**。保留自定义深色 UI，不使用整套通用组件库。

桌面框架采用与 GitKraken 相同类别的 Electron；前端按本项目约定继续使用 Vue。Git 操作直接调用 Git CLI，不需要云端服务器、Python 或 Rust。桌面通过隔离 IPC 调用本机核心；浏览器开发模式通过同源本机接口调用同一套 Git 业务。原 Tauri/Rust 与 Python 实现位于仓库根目录的 `legacy/`，不参与运行和打包。

## 安装与启动

开发需要 Node.js 22.12+、Bun 1.3.14+ 和可运行的 Git。桌面依赖已归入桌面工作区，在仓库根目录统一安装：

```bash
bun install
bun run desktop
```

`bun run desktop` 自动启动 Vite 并打开 Electron 窗口；已有 GitCode 开发服务器时会复用它。开发端口为 **43187**，桌面开发页使用 `http://localhost:43187`。退出启动进程会停止它自己启动的 Vite，不会结束此前已运行的服务。

浏览器预览直接复用本机 Git 核心：

```bash
bun install
bun run dev
```

打开 **http://localhost:43187**，底部显示“本机核心已连接”后，可打开、创建、克隆仓库，执行暂存、提交、同步和已支持的 GitFlow 操作。“浏览”使用应用内目录浏览器，展示本机核心所在系统的实际目录；在 WSL 启动时访问 WSL 路径，Windows 磁盘从 `/mnt/c`、`/mnt/d` 进入，不把浏览器文件句柄伪装为本机绝对路径。更新本机接口代码后须重启开发服务。

启动后显示仓库首页，提供打开、克隆和创建入口；不再内置演示仓库或模拟提交。静态 `bun run preview` 不启动本机核心。未连接时界面提前说明原因，并提供连接入口，不要求用户先选择目录后再报错。当前浏览器接入随开发服务启动，尚未提供独立安装的浏览器连接助手；桌面安装包仍可独立运行。

本机接口绑定回环地址，校验 Host、Origin、浏览器请求来源及随机会话令牌，不开放 CORS，也不暴露任意 Shell 或文件读写接口。每个页面独立维护 Git 队列、取消与计划；关闭页面时尽力释放会话，空闲 30 分钟后过期，最多保留 32 个会话。运行中的操作不因空闲计时过期；关闭浏览器或连接中断不能保证 Git 自动回滚。重新连接不会自动重发操作，需先核对仓库。多个页面或桌面与浏览器同时操作同一仓库仍属于外部并发，需要执行前校验及 Git 自身锁保护，不能视为跨客户端事务。

Electron 的首次安装会下载 Chromium / Node 运行时。根工作区声明信任 Electron 的安装脚本，所有依赖由根 `bun.lock` 固定。

Git 业务使用临时真实仓库验证，前端构建及 IPC mock 也有独立测试；平台安装包和原生窗口需分别进行实机验收。

当前环境若继续在 WSL 调试，可使用：

```bash
bun run desktop:wsl
```

这个可选命令为 Electron 关闭硬件加速，并在 Linux 使用 X11，不再使用 WebKitGTK 环境变量。Electron 的 Chromium 沙箱保持启用。WSL 运行的是 Linux 应用；Windows 原生开发、`.exe` 构建与验证应在 Windows 或 Windows CI 进行。Linux 的 Chromium 还需要系统图形运行库和可用的沙箱环境，具体见 [Electron 官方文档](https://www.electronjs.org/docs/latest/tutorial/sandbox)。

## Windows 窗口与屏幕适配

Windows 使用 Electron 原生窗口按钮覆盖层，最大化按钮交由系统处理；Linux 保留自绘按钮，macOS 保留红绿灯。窗口边界使用 Electron 的逻辑像素，不再额外乘以 DPI 缩放系数。默认尺寸按当前屏幕工作区收敛，最小尺寸为 720×480，并受更小工作区限制；720px 以下的新标签页采用单列。

窗口普通尺寸、位置和最大化状态保存在用户配置目录的 `window-state.json`。重启会恢复并校验当前显示器范围；移除显示器或改变工作区后，窗口会重新收敛到可见区域。最小化状态不会覆盖普通尺寸；配置损坏或写入失败不阻止启动和操作。该文件仅记录窗口布局，不记录仓库授权、认证或 Git 操作状态。

## Windows 原生开发

在 Windows 中安装 Node.js、Bun 和 Git，然后在 PowerShell 中将项目放到 Windows 本地路径（例如 `C:\projects\GitCode`），进入项目目录执行：

```powershell
bun install
bun run desktop
```

Windows 和 WSL 应分别安装依赖，不要共用 `node_modules`。Windows 桌面原生运行时，“浏览”会打开 Windows 系统目录选择窗口；WSL 桌面运行时打开的是 Linux 目录选择窗口，Windows 磁盘通过 `/mnt/c`、`/mnt/d` 等路径访问。浏览器模式使用本机核心的目录浏览器，目录环境取决于启动开发服务的系统，而非浏览器所在系统。

## 桌面弹窗与界面恢复

普通表单使用轻量遮罩，设置窗口使用透明背景，关闭草稿、仓库信任和破坏性操作确认保留更明显的提示层；不对主窗口背景做模糊处理。设置目前仍是模态窗口，保留焦点限制与 Esc 关闭行为。中文输入法组合输入期间，全局应用快捷键不抢占选词，也不触发提交或关闭标签。

桌面主界面加载失败、渲染进程退出或窗口无响应时，由 Electron 显示原生恢复提示，可重新加载界面、打开日志目录或暂不处理。异常记录在活动日志中。重新加载不重试原来的 Git 操作、不回滚更改；后台任务可能仍在执行，恢复后先核对仓库状态。多个同时到达的异常共用一条提示，退出期间不再弹出恢复窗口。

仓库获取范围、补全历史等操作仍在仓库页独立保存或执行；Git 运行环境在设置中验证、保存并即时生效。这些操作不会随外观／字体预览的取消而撤销。

## 文件历史与版本比较

工作区文件或提交文件的右键菜单提供 **显示文件历史**，差异预览标题区也可进入。历史在仓库内部标签打开，以所选提交（工作区入口为当前 HEAD）和当时路径为起点，按页读取，并跟随 Git 识别到的重命名。单击版本预览此次修改；按 Ctrl／⌘ 单击第二个版本比较两者。版本右键提供与本地文件比较、在提交图中定位、复制 SHA 和路径。关闭工具标签或点击左侧工作区／历史导航可返回原视图。

工作区文件右键或差异工具栏的 **比较三个版本** 以只读方式并排展示 HEAD、暂存区、工作区，支持行对齐、修改高亮、同步滚动、修改跳转和两版本模式。读取期间内容发生变化会拒绝混合结果；仓库状态刷新后提示重新读取。冲突文件使用冲突编辑器；二进制、不支持的编码及较大文本不提供内嵌文本预览。三版本比较不执行暂存、覆盖或提交。

提交历史搜索框查询本地已有引用可达的全部提交说明，不再局限于首屏。作者、日期和路径筛选位于同一工具栏，可与分支条件组合，分页显示匹配结果；输入变更会取消旧查询，后台读取可让位于前台 Git 操作。日期按 Git 的提交时间筛选。查询不会自动获取远程对象，也不会将筛选后相邻的两个结果伪装成直接父子提交。SHA 输入继续使用原有定位流程。

## 按块／按行暂存

在工作区点击文件，打开差异后选择 **选择修改**。修改行左侧的复选框用于选择新增或删除行；每个修改块右侧可选择整块，或直接暂存／取消暂存该块。顶部按钮处理所有已选修改行。切换“未暂存内容”和“暂存内容”可分别操作两个来源，“完整改动”仅用于查看；进入选择时会切到对应的可操作来源。

局部操作只更新暂存区，不改写工作文件。提交按钮仍提交全部已暂存内容，因此可以先暂存其中一块，再提交，剩余修改留在工作区。选择绑定文件、分支、暂存区及内容转换设置；文件外部保存后保留旧预览并禁用操作，需要重新读取，重新读取会清空选区。索引在外部被更新时，即使所选文件差异未变化，执行前也会拦截旧预览，避免覆盖别的暂存内容。

支持普通 UTF-8 文本（含 BOM）、CRLF、新增/删除文件、首次提交前的局部暂存、linked worktree 和 SHA-256 仓库。无结尾换行的修改块只支持整块操作；重命名、二进制、LFS／内容过滤器／编码转换、权限变化、冲突、索引 Hook、稀疏/拆分索引及较大文件会说明原因并要求使用整文件或冲突处理操作。预览最多保留 5 分钟；暂存区原文件超过 16 MiB、20 万行或差异超过 300,000 字符时不提供局部操作。

执行通过 Git 自身的 HEAD 引用锁和标准 index.lock 保护，先构造临时索引，重新校验后原子替换真实索引；不会接收前端提供的任意补丁。取消会等待已准备的回调收尾，但取消不等于回滚已经发布的索引结果。进程强杀或系统崩溃仍可能遗留 Git 锁。

## Git 操作恢复

打开仓库后，使用 **编辑 → Git 操作恢复**。支持撤回普通本地最近提交并保留暂存区、工作文件，以及恢复通过 GitCode 删除的本地分支。撤回前保存原提交，可另外创建分支找回；恢复分支不会覆盖同名分支，也不会切换当前分支或修改远端，原上游关联需重新设置。

恢复点以 `refs/gitcode/recovery/` 引用保存在当前仓库中，重启后保留，不计入正常提交图，当前不会自动过期。只覆盖功能加入后通过本应用保存的恢复点；不是所有 Git 操作的通用 Undo/Redo。首次提交、合并提交、游离 HEAD、未完成的合并/变基/GitFlow 流程，以及已有本地远程引用包含的提交，不提供撤回。预览不查询服务器，本地远程引用可能过期，因此撤回前还需确认该提交尚未共享；已共享的提交应使用反向提交。

执行时重新核对仓库、分支和提交，并通过 Git 引用事务校验旧值；提交变更前在 Git 持有引用锁时再次确认实际分支。外部操作使预览过期时需要重新读取。正常取消会请求 Git 中止事务；强制终止应用、系统故障或超时后强杀仍可能留下 Git 锁，不能当作自动回滚承诺。

## 外部仓库变更

当前仓库会自动核对外部编辑器、终端产生的文件修改、暂存、提交和分支切换，回到应用时也会核对。后台读取合并短时间内的重复通知，在 Git 操作、参数对话框或索引锁存在时等待；不会替用户暂存、提交或拉取。提交草稿、输入焦点和正在查看的差异滚动位置会保留，冲突编辑草稿遇到外部变化时提示重新读取。

优先监听 Git 可见目录及仓库元数据，支持 linked worktree；每仓库最多监听 512 个目录，最多保留 3 个仓库的监听，空闲 60 秒后释放。正常状态每 30 秒补充核对，监听不可用或超出上限时每 10 秒补充核对；页面隐藏时暂停读取，重新显示后核对。网络盘和虚拟化文件系统的通知可能延迟，可手动刷新。

## 仓库终端

工具栏右侧的“终端”、视图菜单或 Ctrl+反引号可显示／隐藏底部终端。每个仓库标签拥有独立会话，支持新建、切换、关闭、清屏和拖动调整高度。隐藏面板保留 Shell 与正在运行的命令；关闭终端或所属仓库标签会结束会话。Windows 仓库使用本机 Shell，WSL 仓库通过对应发行版进入 Linux 目录。浏览器开发模式连接本地核心后也可使用终端。

终端使用 xterm.js 和独立 PTY 工作进程，字体跟随编辑器设置，配色跟随主题。桌面启动及打包脚本会准备与当前 Electron 版本匹配的 node-pty：优先验证官方预编译模块，不兼容时单独构建并缓存，不覆盖浏览器核心的 Node 模块。源码构建回退需要目标系统的 C/C++ 构建工具；安装包已包含原生模块，最终用户无需安装 Node.js 或编译工具。原生模块需要在目标操作系统构建，macOS 安装包应在 macOS 上制作。

## 品牌图标生成

修改 `assets/brand/logo-glyph-transparent.svg` 后，运行 `bun run icons:generate`。该命令会同步重建紧凑/浅背景 SVG、三档深浅透明 PNG、16–32px 紧凑 PNG，以及系统 PNG、ICO、ICNS。桌面立体母版为 `assets/brand/logo-master.png`。

界面通用图标使用 [Google Material Symbols Outlined](https://github.com/google/material-design-icons) 的原始 SVG，项目 Logo 保持独立。所需资源随前端本地打包，不加载在线图标字体；资源映射、固定上游版本和校验值位于 `src/assets/icons/material-symbols/manifest.json`，Apache 2.0 许可证和说明位于 `third-party/google-material-symbols/`。收藏星标使用官方实心变体。运行 `bun run test:icons` 可检查资源完整性和许可证打包规则。

透明 PNG 使用锁定版本的开发依赖 `@resvg/resvg-js` 渲染，不需要 Chrome、Playwright 浏览器或系统图片工具。该依赖不进入桌面运行包。运行 `bun run test:icons` 可验证重建、源图变更同步、透明孔洞与浅背景节点颜色；若源图结构变化导致光学调整规则失效，命令会明确报错。修改后仍需重新打包应用，安装包图标才会更新。

## 按钮尺寸与状态

常规命令按钮参考 IDEA 的紧凑比例，以 72×28 CSS 逻辑像素为最小尺寸，使用 4px 圆角、1px 边框和 8px 同组间距。按钮文字随界面字号变化，长文案自然扩宽，大字号通过行高与内边距自然增高，避免裁切。普通图标按钮为 28×28，导航与列表中的紧凑按钮为 24×24；图标保持原有用途对应尺寸，不随按钮点击区域机械放大。与输入框配套的浏览按钮保持与输入框等高。

主按钮沿用所选主题的强调色；普通、危险、禁用和键盘焦点使用各自状态，按下不产生位移。原生窗口按钮与系统对话框仍由操作系统管理。

## 界面字体

平台边界由 `electron/platform.cjs` 统一选择 Windows、macOS、Linux 适配器，各适配器负责 Git 候选路径、开发工具解析、子进程环境和系统字体命令。`git-runtime.cjs` 只保留共享的选择策略、版本验证、诊断和回退流程；系统字体结果由 `fonts.cjs` 统一规范化。平台模块采用普通 CJS 文件，随桌面运行代码一并打包，不依赖额外原生扩展。

界面平台由原生预加载元数据或浏览器自身识别，不采用 Git 服务返回的平台；Git 运行环境单独记录。Windows 浏览器连接 WSL 时使用 Windows 字体与快捷键，Git 命令仍由 Linux/WSL 执行。浏览器字体读取按本地字体 API 的能力与授权处理，不使用 Git 服务器的系统字体列表。

设置窗口使用左侧分类、右侧配置与固定底部操作按钮。在“文件 → 设置 → 字体”中通过“界面／编辑器”两个用途页分别配置字体，支持主字体、中文等字符的后备字体、中英文和代码预览，以及分别恢复默认。桌面版读取本机已安装字体；支持相关 API 的浏览器可授权读取，其他环境可直接输入字体名称。界面字号范围为 11–16px，编辑器字号为 10–24px；编辑器另外支持 1.2–2.2 倍行高和连字开关。设置窗口内修改即时预览；“应用”保存并保留窗口，“确定”保存后关闭，“取消”、关闭按钮和 Esc 恢复到最近一次应用的状态。预览不写本地配置，保存失败保留输入并明确提示；已完成的部分写入会尝试恢复，恢复失败则提示核对。

界面字体覆盖文件／编辑／视图等应用内菜单、仓库标签与工具栏、仓库导航、工作区变更、提交历史、提交说明和表单，包括其中的路径与提交标识。界面字号整体联动，标题与辅助信息保留相对大小。只有差异、历史文件、补丁和冲突编辑器的代码正文及行号使用编辑器配置。

自定义设置默认关闭，保留原有字体、字号和布局；关闭自定义仅停用效果并保留个人选择，分别恢复默认才会重置对应一组。编辑器自定义未启用时显示默认状态说明，不展示一张无法代表所有区域默认值的统一预览；启用自定义编辑器字体后，差异、历史文件和冲突编辑区域共用所选编辑器字号与行高。系统窗口按钮与原生菜单仍使用系统字体。

浏览器读取的是浏览器所在系统的字体，与 Git 服务运行在 Windows、WSL 或其他环境无关；字体访问权限按站点管理，`localhost` 与 `127.0.0.1` 需分别授权。拒绝授权后可在地址栏的站点设置中调整“本地字体”权限，或直接输入字体名称。应用不会用 WSL/Linux 的字体列表替代 Windows 浏览器的字体列表。

界面与代码区优先使用 **Cascadia Mono（英文）+ Microsoft YaHei／微软雅黑（中文）**。Cascadia Mono 常规体与斜体来自微软官方发布，采用 SIL Open Font License，作为 WOFF2 随应用打包；微软雅黑调用系统已有字体，不附带系统字体文件。它作为常用系统字体始终出现在候选列表中，显示“微软雅黑 · Microsoft YaHei”，支持中英文搜索并合并中英文别名；“系统”标记不表示随应用内置或已检测到安装，缺失时仍使用后备字体。缺少微软雅黑的平台使用已打包的 Noto Sans SC 中文后备字体。字体资源已下载；需要校验或重新安装时运行：

```bash
bun run fonts:install
```

字体与授权保存在 `public/fonts/`，生产构建会一并打包，运行时无需访问字体网站或安装 Cascadia Mono。`public/fonts/manifest.json` 记录来源、字重、样式与 SHA-256；安装脚本复用已有且校验正确的文件。

完整中文后备字体保留任意中文仓库名称的离线覆盖。Windows 下若系统安装了微软雅黑，浏览器及桌面端会优先使用它；WSL/Linux/macOS 未安装该字体时正常回退。

字体来源与授权：[Cascadia Mono](https://github.com/microsoft/cascadia-code/releases/tag/v2407.24)、[Noto Sans SC](https://github.com/google/fonts/tree/main/ofl/notosanssc)。同时内置 Inter、JetBrains Mono、Fira Code、Source Code Pro、Roboto、Noto Sans，均保留 OFL 授权。新增字体来源锁定到 Google Fonts 提交，详见 `src/fontCatalog.json`。

字体下拉支持独立搜索和键盘选择，打开时展示全部候选；标有“内置”的 8 个字体家族无需读取本机字体或联网即可选择。界面可选 Inter、Roboto、Noto Sans，代码可选 Cascadia Mono、JetBrains Mono、Fira Code、Source Code Pro；Noto Sans SC 提供中文后备。默认字体保持不变。

界面采用中性深灰分区、分级字号、30px 历史行与默认32px单行文件列表。历史列表与图谱共用行高；主引用及 `+N` 可查看完整列表。小于1600px的窗口隐藏作者和时间独立列，完整信息仍在提交详情中查看。

图标采用独立的普通、悬停、按下、禁用和键盘焦点颜色；当前 Git 分支使用绿色，当前查看对象使用蓝色，悬停保留已有状态。GitFlow 折叠和行操作使用 24px 宽点击框，沿用原图形中心与行内总占位；箭头只表示实际折叠或下拉，分支切换用双向箭头。分支下拉支持外点、焦点离开和 Esc 关闭，Esc 返回触发器；右键菜单与确认对话框可临时取焦。相关边界、状态和焦点已纳入浏览器脚本，实际视觉与缩放效果仍需运行验证。

## 打包

Windows 本地目录提供一键打包入口（需提前安装 Node.js 22.12+ 和 Bun）：

```powershell
.\apps\desktop\build-windows.cmd
# 或
bun run desktop:build:win
```

脚本会安装工作区中锁定的桌面依赖、执行类型／代码风格检查、构建前端，再生成使用系统 Git 的 Windows x64 安装包，输出 `release\desktop\1.0.1\GitCode Setup 1.0.1.exe`。以上命令在仓库根目录运行；如果已进入 `apps/desktop`，使用 `.\build-windows.cmd`。任一步失败即停止。复用已安装的 Windows 依赖可加 `-SkipInstall`；仅检查环境可运行 `.\apps\desktop\build-windows.cmd -CheckOnly`；ARM64 构建使用 `-Arch arm64`。不要从 `\\wsl.localhost\...` 路径运行，先复制到 Windows 本地磁盘。

先安装两处依赖，然后在目标系统执行：

```bash
bun run desktop:build
```

安装包不再附带 Git，也不会在构建时下载 PortableGit。Windows 的 `beforePack` 只准备 WSL 核心所需的 Linux Node 运行时，校验固定 SHA256，并保留许可证；用户无须额外安装 Node。旧的本地 PortableGit 缓存不会进入新安装包。

各平台均使用所在环境中的 Git，不再按 2.46 统一拦截；勾选提交和变基按实际命令能力检查与适配，Windows 会检查 PATH 和常见安装位置。未找到时提供“安装 Git”“选择已有 Git”和“重新检测 Git”；安装链接打开对应平台的官方安装说明，不自动执行安装命令。**文件 → 设置 → Git** 显示当前来源、版本和路径，可选“自动查找”或“自定义 Git”，验证、保存后即时生效。检测或保存失败时保留原运行环境，有 Git 操作时禁止切换。旧的“系统 Git”选项兼容为自动查找。`GITCODE_GIT_PATH`（兼容旧名 `GITK_GIT_PATH`）作为显式环境变量覆盖，优先于界面设置。用户 Git 配置、SSH 密钥和凭证仍使用当前用户环境，不随安装包分发。

已确认信任的仓库会向 GitCode 启动的 Git 进程传入该仓库规范路径的 `safe.directory` 例外，解决 Windows 目录归属 Administrators 组而当前账户为具体用户时的所有权检查。此例外不写入全局 Git 配置，不包含其他仓库；首次确认和已有信任记录均可使用。目录或执行相关配置变化仍需重新确认。

macOS 会额外检查 Apple Command Line Tools、Xcode、`DEVELOPER_DIR` 指定的开发工具路径，常规位置失败后通过 `xcrun --find git` 定位。检测失败会保留实际标准错误输出，详细路径默认折叠；终端可运行但应用失败时，可用 `command -v git` 和 `xcrun --find git` 确认完整路径后配置自定义 Git。安装开发工具后可使用“重新检测 Git”或启动页“重试”，已有有效 Git 的运行会话不会被静默切换。

Mac 自动模式优先探测 Homebrew（`/opt/homebrew/bin/git`、`/usr/local/bin/git`）、MacPorts（`/opt/local/bin/git`）、独立安装（`/usr/local/git/bin/git`）、Apple 开发工具实际路径及 `xcrun`，最后回退到 PATH 和 `/usr/bin/git`。每个候选均执行版本检查；显式环境变量及自定义路径保持优先，不因失败而静默换用其他 Git。不扫描整个磁盘或运行中的 Git 进程。

产物统一在 `release/desktop/<版本号>/`，例如 `release/desktop/1.0.1/`。同版本重新打包前，已有安装包及更新文件会自动复制到该版本的 `history/<UTC时间>-<编号>/`，保留当前文件直至构建过程替换；不会复制体积较大的 unpacked 目录。已配置 Windows NSIS `.exe` 安装包、macOS `.dmg` / `.zip`、Linux AppImage / deb。也可以指定目标，例如：

```bash
bun run build
node scripts/package-desktop.mjs --win --x64
```

公开分发前仍需准备 Windows 代码签名、macOS 签名/公证和更新策略，并完成实机测试。手动触发的 `.github/workflows/desktop-validation.yml` 提供 Windows x64、macOS arm64/x64 的未签名验证构建，不自动发布版本。

**安装后的应用无需安装 Node、Bun、Python 或 Rust，也无需启动服务。** 各平台均需安装可运行的 Git；WSL 仓库使用对应发行版中的 Git。

## GitFlow

左侧 **GitFlow** 标题展开或折叠分类，右侧“操作”打开日常操作面板，设置从面板进入。浏览器连接本机核心后与桌面模式使用相同的真实 Git 操作；未连接时仅可预览。

- **配置**：生产分支、开发分支、Feature／Release／Hotfix 前缀与可空的标签前缀。读取和写入标准 `gitflow.branch.master`、`gitflow.branch.develop`、`gitflow.prefix.*` 仓库配置，不需要安装 git-flow 扩展。保存不创建或移动分支。
- **初始化**：为每条缺失的本地基础分支选择起点：支持现有本地分支，或已获取的远端同名分支。提供显式“获取”入口；唯一远端候选可预选，多远端必须明确选择。预览与确认均核对远端实际 OID；恢复后建立对应上游，不切换、推送或移动已有分支。再预览创建与保留列表。五分钟内的一次性计划绑定仓库、HEAD、配置和起点 OID；事务只创建缺失引用，不覆盖已有分支，也不切换工作区。引用与配置不是一个事务；若后续配置保存失败，会报告结果待核实并重读状态，不声称自动回滚。
- **开始**：Feature、Release 基于本地开发分支，Hotfix 基于本地生产分支。填写后缀时就地显示全名和起点，默认创建后切换，可取消勾选；SHA 按需展开。要求干净工作区、无未完成 Git 操作；不自动获取、stash 或推送。切换失败会明确报告分支已创建，需刷新核对后再操作。
- **分类**：仅归类匹配规则的本地分支，与“本地分支”共享引用身份、当前标记、收藏与历史筛选语义；入口选中边框单独记录，只显示在实际选择的入口。数量不可相加作为总数；前缀不表示任务仍在进行或尚未合并。
- **完成（Finish）**：从工作流分支右键选择“完成功能分支／完成发布／完成热修复”，确认窗口绑定该分支；操作面板的“完成分支…”提供分支选择。Feature 合入开发分支；Release／Hotfix 先合入生产分支，再将生产分支合回开发分支。使用 Merge，不使用 Rebase。Release／Hotfix 默认创建附注版本标签，标记生产分支的合并结果，也可取消标签。完成后默认删除本地工作流分支，可选择保留；最终停留在开发分支。不自动获取、推送或删除远端分支。
- **冲突与恢复**：执行前核对干净工作区、配置、源及目标提交、标签冲突和其他 worktree 占用。逐步写入当前 worktree 的 Git 目录进度记录；冲突时暂停，使用三栏合并工具处理。“完成当前合并并继续”自动衔接余下步骤；关闭、重启或外部完成合并后，可根据记录继续，不重复已完成步骤。中止当前合并后可“停止后续步骤”，保留已完成提交、标签、源分支和新工作区修改，不承诺回滚。引用被外部修改时停止并显示原因。

交互依据 [GitKraken 官方 GitFlow 文档](https://support.gitkraken.com/gitkraken-desktop/git-flow/) 和 IDEA 的 [Git Flow Integration 插件实现](https://github.com/OpherV/gitflow4idea)。IDEA 插件不是 IDEA 内建功能，也有不同实现；本项目直接使用 Git，不依赖外部 git-flow 扩展。三轮真实 Windows Chrome 验证、截图与研究记录保存在 `design/gitflow-finish/`。修改本机核心后必须重启开发服务或桌面应用；旧核心会显示更新提示，禁止执行不支持的 Finish。

GitFlow 未配置或缺基础分支时，开始分支和完成入口禁用，并就地说明原因；设置、补齐和核对入口保留。Start 入口不校验尚未填写的名称，规则就绪且工作区有修改时仍可准备表单，最终创建才检查工作区、名称和起点。有效的只读规则仍可 Start，只禁止保存及初始化配置。基础分支已存在时，初始化预览灰显，直接保存规则即可；草稿改名产生缺失分支时重新要求选择起点。断线后不显示绿色就绪，重连后仍须刷新核对；既有操作结果可继续查看，不能借此绕过执行保护。

“补齐基础分支”会直接定位设置中的补齐区域，并聚焦首条缺失分支的起点选择。必须明确选择起点后才可预览；确认计划同时保存规则并创建缺失引用，无需先单独保存。预览后定位计划，执行后定位结果，就绪时提供“开始新分支”入口。补齐不会切换工作区，现有暂存、未暂存及未跟踪文件保留；后续 Start 创建仍要求处理工作区修改。该链路已通过状态集成、本机 HTTP 中间件及连接真实 Chrome 的浏览器验证，包括滚动、焦点、点击，以及临时真实仓库中的三种 Start、可选切换、名称冲突和完成确认；浏览器报告见 `design/local-core-verification.json`。

表单草稿按仓库路径保存在本机应用存储，版本 2 同时记录配置编辑基线。外部更新后，未编辑字段采用仓库新值；同字段冲突须显式选择采用仓库规则或保留修改，选择不会自动保存。旧格式无法判定哪些字段曾被编辑，规则只作为待确认候选，不自动套用；名称和类型可恢复。收起和切仓不会执行或移用到别的仓库；同一会话内保留原起点与对应操作结果，外部变化后须显式核对。重新启动只恢复输入，明确重新读取起点，不恢复初始化执行计划；Finish 进度另从 Git 目录中的实际记录恢复。存储不可用时草稿仅在本次会话保留。配置保存使用 Git 配置锁约定并保留其他设置，只清理本次取得的锁，不删除非自有锁；异常残留须核对。配置键只归一 section 与最终变量名大小写，保留 subsection 的大小写。来自全局/include 的 GitFlow 规则、独立 worktree 配置及配置符号链接暂不支持在应用内编辑。支持读取这些规则，若规则完整有效且基础分支存在，可用于 Start；重复规则须先整理。

按钮条件统一在 `src/stores/gitflow.ts` 中计算，按钮禁用与提交方法共用校验；主进程仍使用 Git 复核。保存默认规则不要求表单先有改动，已保存且未改变的有效规则才禁用保存。初始化检查首次提交、未完成操作、分支目录冲突和明确起点；确认还检查计划期限及引用变化。Start 检查合法且不冲突的名称、完整配置、干净工作区、未完成操作与固定起点。导航、切换类型和恢复规则不会悄悄更新原操作上下文；须显式刷新核对。确认初始化时再次检查当前时钟，不能只依赖到期计时器。Start 切换前再次核对 HEAD、源与新分支，这只缩小外部并发窗口，不是跨进程锁。应用前后端统一不接受分支后缀中的空白字符，这是本应用的更窄命名策略。刷新同步未编辑的规则，对冲突字段要求明确选择；恢复规则只恢复配置，不清除 Start 名称。

GitFlow 设置使用共同靠左的最大 640px 内容容器。基础分支与命名前缀分组，普通字段采用 128px 标签、16px 间隔和最大 360px 输入列，输入高 34px、字号 13px；字段帮助可用键盘展开，冲突与旧草稿完整保留并自然增高。可用内容宽度不足 560px 时转为单列，窄窗设置导航改为顶行。应用全局最小 CSS 宽度仍为 860px，物理小窗口叠加大比例缩放的裁切尚需实机检查，不能仅以无横向滚动作为验收。布局用例已通过本机缓存的 Chromium，并使用现有 Chrome 验证实际交互；原生桌面窗口和不同系统缩放仍需分别验收。

运行中仍沿用应用现有 Git 操作队列与退出等待／取消流程。第一阶段没有长期运行的 Finish 任务或跨重启续跑承诺。浏览器与本机 Git 核心已完成真实交互验证，Windows/macOS 原生窗口和退出流程仍需独立实机验收。

## 主页面交互约束

提交方法和快捷键共用工作上下文检查：查看历史、打开任意 GitFlow 面板或模态窗口时，不执行隐藏的工作区提交。`Ctrl/Cmd+K` 会收起 GitFlow 并保留草稿，再聚焦可见的历史搜索。覆盖区域不进入键盘焦点；关闭差异返回来源文件，来源消失时返回稳定导航入口。

重新打开已有仓库标签时，通过同一快照应用流程更新选中的工作区差异；固定提交 OID 的历史内容保留。提交详情和差异的读取失败在面板内显示错误和重试，不能显示为真实空结果。侧栏筛选与其他仓库状态一起按标签保存；克隆和创建分别保留目标草稿。空仓库显示首次提交提示。

同步弹窗提供内部取消入口。准备阶段取消使本次计划失效，并在核心确认取消后停止 HTTP 同步目标／快照读取，不误报断线，不执行或重放迟到计划。执行阶段请求取消后保持忙碌，等待实际结果与状态核对；取消不等于回滚，结果弹窗不自动关闭。即使取消确认失败，也不会继续执行已放弃的准备计划。Git 忙碌时禁用新业务弹窗入口，帮助仍可阅读和关闭；任务完成只关闭自己的弹窗。

通知最多保留三条，优先保留错误，限制在历史列内并保留关闭和文本选择，避免遮挡整个提交区及历史搜索。修正记录见 `design/mainpage-fixes/report.json`；原始问题、角色质疑和复现截图见 `design/mainpage-audit/`。

深色界面文字按角色使用 `--text`（主内容）、`--text-secondary`（普通说明）、`--muted`（元信息）和 `--control-disabled-color`（不可操作控件）。选中行元信息使用 `--text-on-selection`，正常解释和禁用原因不随按钮一起变暗。分支、选择、警告与增删状态继续使用各自语义色。配色前后对照和 Chrome 抽查记录见 `design/color-review/`。

工作区使用“未暂存／已暂存”双区，默认列表显示，可在视图菜单切换目录树和连续目录压缩。只有文件与区标题有复选框，目录仅用于展开。文件名打开所属区域的差异，行内 `+／−` 完成单文件暂存／取消暂存；勾选用于所属区的批量操作，不决定提交范围。提交按钮始终显示“提交全部已暂存（数量）”，提交实际暂存区的全部内容。

同一路径部分暂存时在两区分别出现，未暂存差异为 Index→Working，已暂存差异为 HEAD→Index；两处勾选互不联动。区标题全选当前筛选匹配的所有文件，包含折叠目录中的文件。改变筛选保留选择，批量栏明确显示隐藏选择数量；提交总数不随筛选变化。操作失败保留仍有效的选择与草稿；普通刷新去除失效选择，分支或 HEAD 变化清除旧选择。勾选仅在当前会话按仓库和分区保留，新文件不自动勾选。

历史提交与工作区均默认“紧凑”（32px单行），可切换“详细”（40px双行）；两类密度偏好独立保存在本机。切换显示不改变文件、差异与提交草稿。首版不提供模块识别、多变更列表或局部行块提交，不把一级目录伪装成 IDE 模块。原有隔离索引的“提交所选完整文件”能力保留为内部接口与回归测试，不作为当前工作区的交互模式。

切换分支遵循普通 Git 规则：能够安全保留的修改随工作区切换；存在覆盖风险时，保留原分支及文件，并显示“本地修改阻止切换”。可取消，或明确选择“贮藏并切换”：保存全部已暂存、未暂存和未跟踪文件（不含被忽略文件），随后切换，保留贮藏供手动恢复。确认绑定仓库、HEAD、目标分支、暂存区、文件内容及配置；变化后拒绝旧确认。贮藏未完整完成时不切换；贮藏成功但切换失败时报告部分完成，保留记录，不自动恢复或重试。目标新增路径会覆盖本地被忽略文件时直接阻止，不能用不包含该文件的贮藏绕过。真实 Chrome 验证结果和截图见 `design/protected-checkout/`。

恢复贮藏默认恢复文件内容；“恢复原暂存状态”为可选项。启用该选项可能因目标分支差异失败；默认不强求还原旧暂存区，以便内容冲突进入三栏处理。贮藏本身仍保存原暂存和工作区版本。

贮藏（Stash）在选中“未提交的更改（WIP）”且有可处理修改时可创建；历史提交、未完成操作、未解决冲突或首次提交前显示禁用原因。工具栏“贮藏”直接执行，名称及包含范围在工作区底部“贮藏”页签内编辑；关系图和左侧列表用于选择记录。创建、预览、Apply／Pop 均不弹出贮藏管理窗口。创建默认包含未跟踪文件、不含忽略文件，范围为全部工作区修改，与双区 checkbox 和筛选无关；提交说明草稿保留。子模块内部修改须在子模块中单独处理。

合并远端更新（Merge）：推送因非快进被拒绝时，可“获取并检查更新”；拉取弹窗保留“仅快进”，并提供明确选择的“合并远端更新”。后者获取固定目标提交后执行合并；快进直接完成；分叉时无冲突自动创建合并提交，有冲突则在右侧面板暂停，解决后明确完成合并。普通拉取不自动推送；明确选择“拉取并推送”时，仅无冲突且再次核对通过才续推。合并前检查远端新增路径是否与本地被忽略的文件重名，冲突时停止并保留本地内容。第一版不提供 Rebase。非当前分支的推送被拒绝后，要求先切换到该分支，不把当前工作区的分支当成原推送目标整合。

真实文件冲突自动打开列表，双击文件进入中央三栏处理：当前分支、可编辑结果、合入版本。支持整文件采用一方、按冲突块采用一方／双方、手动编辑与查看共同基础。“保存并标记已解决”写入并暂存该文件；所有冲突解决后另行“完成合并”。未完成的合并保存在 Git 原生状态中，关闭列表或重新打开仓库仍可继续，也可明确确认后中止。未保存的编辑草稿按仓库标签隔离，并纳入关闭标签／退出确认；磁盘上的已解决结果可在刷新后继续，未保存草稿不跨页面刷新持久化。

冲突读取与保存核对 HEAD、分支、合并目标、索引、Git 配置及文件内容；外部变化拒绝旧结果覆盖，当前草稿保留。文本编辑限 UTF-8、256 KiB，支持 CRLF；二进制或较大普通文件可采用完整一方；单文件超过 64 MiB、无法安全读取、符号链接及子模块等特殊冲突需外部工具处理。贮藏恢复冲突会自动打开文件列表，也可从状态条重新进入三栏处理工具；处理后保留工作区修改，不提供 Merge 完成／中止，也不自动删除贮藏。原生索引保留冲突状态，重新打开仓库后仍可继续。Git 原始同步错误放入可展开详情，主提示说明分叉及下一步。实际 Chrome 截图与临时远端验收结果见 `design/merge/`。

仓库导航的 GitFlow 与本地分支共享同步状态：当前分支勾选与 `↑领先数／↓落后数` 同时显示，双方分叉时保留两个计数。未设置跟踪关系时，导航和顶部不显示“无上游”或“未设置上游”；首次推送时提供可编辑的远程与目标分支，默认优先使用分支 pushRemote、remote.pushDefault、origin 或第一个命名远程；成功推送后建立关联。修改目标后须先核对，取消不写入远端或关联配置。右键推送入口保持可进入。已配置但引用缺失时保留“上游缺失”提示。远程分支、标签不显示本地上游提示。顶部当前分支使用同一解析规则；计数基于本地引用，获取后才能知道远端更新，普通刷新不访问服务器。

提交图谱仅在实际工作区变更数量大于 0 时显示“未提交的更改”行及其独立圆点；变更清零后移除整行占位，提交、引用连线与贮藏节点同步上移，侧栏工作区入口保留。暂存、未暂存及未跟踪文件均计入，与搜索和文件筛选无关。

贮藏会在关系图显示独立归档节点及到保存时基础提交的虚线，贮藏与普通提交按历史行顺序统一分配轨道：顶部的新贮藏先占用第一条可用轨道并为基础提交预留该轨道，后续分支提交使用剩余轨道。不会把贮藏追加到已固定的普通提交图右侧；普通提交计数不含贮藏。内部索引和未跟踪文件快照不作为普通分支合并节点展开。工具栏仅保留创建贮藏入口；恢复操作位于具体记录的详情与右键菜单。单击节点／行后右侧 Inspector 显示贮藏文件，点击文件复用中央差异区域，可切换完整工作区版本与原暂存内容；右键 Apply／Pop 直接执行，删除才打开具体记录确认。WIP、历史提交与贮藏选择互斥，切换仓库／标签页时隔离读取，返回标签页可恢复贮藏差异来源和提交草稿。基础提交超出加载范围时显示边界提示。图谱搜索可匹配贮藏名称、创建时分支与对象 ID。贮藏是仓库共享记录，不归属于某个分支，分支历史筛选不会隐藏贮藏；连线只指向创建时的基础提交，不随当前分支改接。基础提交不在筛选视图时保留节点及边界提示。“创建时分支”仅作说明，可以恢复到其他分支。

恢复明确区分 Apply（保留记录）和 Pop（成功后移除），均恢复到当前分支，不自动切换。首版要求当前工作区干净，默认尝试恢复原暂存状态，可取消；冲突或取消可能留下部分恢复，记录保留并提示检查，不自动重试、清理冲突或强制回滚。删除必须确认具体名称。执行前核对仓库、分支、HEAD、贮藏列表签名及记录 OID／位置，Pop 恢复后再次核对列表再移除，列表变化则保留记录。外部 Git 并发修改仍需刷新复核，不以缓存序号单独定位。实现与真实 Chrome 验证记录见 `design/stash/`。

深色主界面参考用户提供的 GitKraken 截图进行颜色分层：图谱底色 `#1c1e23`、面板 `#272a31`、工具栏 `#33373f`、历史选中 `#25334f`、当前分支 `#37553e`。正文采用中性灰，元数据与禁用状态独立；品牌强调色、图谱轨道与 Git 变更状态各自保留语义。主强调色采用青蓝 `#22b8d0`，当前分支继续用绿色区分。图谱使用八种较高饱和度的青、紫、蓝、品红、橙红等轨道色；节点、连线和引用标签由同一轨道颜色派生，引用行增加轻微色带，选中行保持统一深蓝以保证轨道清晰。颜色来源是截图采样，不能视为官方主题变量。实测与对比度记录位于 `design/gitkraken-palette/`。

引用标签采用独立当前勾选、名称和本地电脑／远程云／Tag类型图标。仅当本地分支明确跟踪某远程且双方指向同一提交时合并显示；云按钮只读查看远程引用，正文保留本地切换目标。“+N”按额外标签组计数，提示同时给出全部原始引用数。

标签列保持固定宽度：名称悬停或键盘明确聚焦时，整组标签、云按钮和“+N”向右浮动展开，不移动列宽和提交节点；直接进入云／“+N”热区不会触发展开，避免目标移位导致误切换。展开受历史面板可视右边界限制，极长名称仍有完整引用提示。

提交图中的引用定位线从标签组（含“+N”）末端连接到同一提交节点，表示引用指向关系，不计作父子边。当前检出本地分支所在提交使用2px全色定位线，其他引用使用1px、25%不透明度的实线；提交选中不改变这层强调。虚线用于缺失父提交边界，不能与淡实线混用。工作区节点是独立入口，不绘制通向 HEAD 的父子边，也不优先占用真实提交轨道。无可见引用的提交不显示定位线；隐藏的远程 HEAD 别名也不产生定位线。跨轨道父子边在行间使用圆角折线，过滤或250条加载边界之外的父提交仍显示虚线截断；交叉处没有圆点不表示提交相连。

提交树中的本地分支标签单击尝试切换，携带当前仓库上下文与目标OID校验，不强制覆盖本地修改；当前分支不重复执行。远程引用、标签及“+N”保留引用查看入口。侧栏仍采用单击筛选、双击打开切换确认。切换失败保留历史选择、筛选与提交草稿；真实浏览器验证使用独立临时仓库，覆盖覆盖冲突拒绝、成功切换、双击去重和引用弹窗。

## 侧栏分组与层级

## Git 命令策略与审查

顶部与右键共用受限业务接口，写操作核对仓库、分支和 HEAD；指定 SHA 创建使用固定基点，不从执行时的 HEAD 推导。同步前主进程生成5分钟有效、一次性计划，执行前复核有效配置（含 include/worktree 配置）、地址与源提交。界面只展示分支去向、脱敏地址和具体限制，不返回配置原文。

| 操作                         | 最终命令边界                                                                                                                                                    | 原因与限制                                                                                                                                                                              |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 获取                         | 按命名远程逐个 `fetch`（遵循 skipFetchAll），显式安全 heads→该远程 refs/remotes 映射，空 refmap                                                                 | 不自动取标签、不 prune、不递归子模块；拒绝会写 heads/tags 的配置，保留逐远程结果                                                                                                        |
| 拉取                         | 显式 fetch 到独立临时 ref 及上游跟踪 ref，取得确切 OID；选择仅快进时使用 `merge --ff-only --no-autostash`，选择 Merge 时使用 `merge --no-commit --no-autostash` | 要求无未完成操作；本地修改先自动贮藏，主要操作完成后尝试恢复；冲突保留记录，解决后显式完成合并；临时 ref 按原 OID 删除                                                                  |
| 冲突处理                     | 从索引阶段读取基础／双方版本，保存指定文件后 `git add`；删除选择使用 `git rm`，完成执行 `git commit`，中止使用 `git merge --abort`                              | 校验读取令牌及仓库／索引／内容签名，不以普通提交入口绕过冲突处理；合并钩子失败保留未完成状态                                                                                            |
| 推送                         | 命名远程、单个 `OID:refs/heads/目标`，`--no-force --no-follow-tags --recurse-submodules=no`                                                                     | 不受 matching 扩大范围；拒镜像、自定义推送映射、多地址等不支持配置；首次发布明确目标后推送，成功后才建立关联；目标优先 pushRemote/pushDefault，三角工作流使用同名目标，确认页完整展示   |
| 暂存                         | `add --` 加当前变更中选定的字面路径，重命名包含原路径                                                                                                           | 不接受任意路径或过期路径；文件仍可能被外部程序修改                                                                                                                                      |
| 取消暂存                     | 有 HEAD 使用 `restore --staged --`，初始提交前使用 `rm --cached --`                                                                                             | 保留工作文件，不调用 discard/reset                                                                                                                                                      |
| 提交所选完整文件（内部接口） | 五分钟一次性计划，使用隔离索引构建所选内容，执行原 hooks 并校验最终提交范围，成功后更新真实索引中的所选路径                                                     | 保留未选文件的已有暂存；执行前复核 HEAD、分支、索引与所选内容。部分暂存需显式确认。稀疏／拆分索引、所选子模块或超过64MiB的文件使用明确的暂存区模式；原生 Windows/macOS 事务仍需实机验收 |

| 恢复贮藏                     | 按 OID 执行 `stash apply`，可选 `--index`；Pop 成功后再核对并 `stash drop`                                                                                      | 当前工作区需干净；冲突保留记录与现场，不强制 reset、不自动重试                                                                                                                          |
| 删除贮藏                     | 核对列表签名、OID 与位置后 `stash drop`                                                                                                                         | 须明确确认名称，工作文件保留；不提供清空全部                                                                                                                                            |
| 工作区提交                   | `commit -m`，不带 `-a` 或文件列表                                                                                                                               | 提交 Git 当时的全部暂存区，保留 hooks 与签名；失败后检查 HEAD/索引变化，结果不明保留草稿，不自动重试                                                                                    |

| 读取/差异                    | refs、log、status 使用结构化字段，SHA/路径校验；diff 禁外部驱动、textconv、颜色                                                                                 | 分支名中的逗号不再拆分；注解 tag 关联目标对象；图谱最多250条，边界表示未加载；禁懒取对象，缺失对象会报错                                                                                |

Git 操作无论成功、失败或取消，都尝试在独立、限时信号下重读状态；分别报告操作错误、清理错误和刷新错误。刷新保留有效的历史详情、差异和草稿。推送通信失败不能证明远端毫无变化，应先获取核对。

保留命名 remote，避免直接传有效URL造成二次重写及 hook 远程名变化；冻结 OID 推送会使 pre-push hook 输入的源引用显示为 OID，依赖分支名的脚本可能需要适配，失败不会绕过 hook。配置/HEAD 复核是变化检测，**不是对外部 Git 进程的跨进程锁**。Git 检测不再设置统一的 2.46 门槛；勾选提交在写入前检测 Hook stdin 和 pathspec 文件选项，变基根据命令能力使用 `--empty=stop` 或旧版 `--empty=ask`。能力检测结果按运行环境缓存，切换 Git 后失效。已使用 Windows Git 2.45.2 验证提交、钩子和变基；这不表示全部历史版本或 macOS 已通过验证。Git 来源、升级和安全补丁由用户或企业 IT 维护。

本轮三轮质疑收敛：第一轮拆清界面承诺与 Git 配置；第二轮检查 refspec、URL重写、hook 和共享 FETCH_HEAD；第三轮确认命名远程、固定提交、独立恢复、部分成功与兼容限制。策略参考 [GitKraken 同步说明](https://help.gitkraken.com/gitkraken-desktop/pushing-and-pulling/)、[Git fetch](https://git-scm.com/docs/git-fetch)、[Git push](https://git-scm.com/docs/git-push)、[Git hooks](https://git-scm.com/docs/githooks)。

## Git、权限与当前限制

本地分支右键菜单区分所选分支与当前工作区：可推送指定分支；未关联远端时提供首次发布目标，确认页展示完整本地引用、提交和远程目标，不切换工作区，也不包含未提交修改。计划会核对所选分支、当前 HEAD 和配置的变化；重新读取目标时刷新仓库并保留原分支身份，分支被删除时不会改为推送当前分支。非当前分支的拉取入口置灰并提示先切换；当前分支拉取支持仅快进和快进或合并；未提交修改按自动贮藏恢复流程保护。首次发布支持选择已有远程和目标分支；内容已推送但关联失败时报告部分完成，不自动重复推送。远程地址的新增与修改仍需通过外部 Git 配置。

GitFlow 分支菜单提供真实 Finish，确认后执行合并、可选标签和本地分支清理。已实现但状态不满足的命令显示禁用原因；尚未实现的普通分支合并、变基、reset 等命令不放入菜单。分支管理、复制和删除分别分组，删除位于独立尾组。

渲染进程启用 `contextIsolation`、沙箱，禁用 Node 集成。预加载脚本仅暴露命名业务接口，不暴露任意 IPC、`require`、Shell 或文件系统 API。主进程校验窗口、顶层 frame 和页面来源，阻止非应用页面导航；外部帮助链接有固定白名单。生产资源随应用打包，通过文件加载，独立运行。

Git 使用参数数组调用，不使用 Shell 拼接命令。按 PATH 和常见安装位置发现 Git，也可设置 `GITCODE_GIT_PATH` 指定完整路径。保留既有 Git 凭据助手、SSH、签名和代理配置，禁用终端密码输入和懒取对象；尚无应用内 OAuth / SSH 密码输入界面。

取消不是回滚，可能留下部分更改、部分克隆或锁文件，需刷新检查。新仓库目标必须不存在，父目录必须存在。历史每页 250 条、支持继续分页，文本差异最多 300,000 字符，单次 Git 输出上限 32 MiB，目录浏览最多 2000 个子目录。

Windows 原生应用通过独立的 WSL 核心访问 `\\wsl.localhost\...` / `\\wsl$\...` 仓库，使用对应发行版的 Git。文件监听和逐行暂存已有专项实现；图片差异和自动更新尚未实现；Windows、macOS/Linux 及 WSL 仓库均使用各自环境中的 Git。Merge 与基础三栏冲突处理已提供，特殊文件类型和较大文件仍需外部工具。目录浏览、系统窗口行为和安装包仍需跨平台验收。

## 代码结构

Windows 版支持从“文件 → 打开 WSL 仓库…”或新标签页的同名入口浏览已安装的发行版，也可直接输入 `\\wsl.localhost\Ubuntu-26.04\home\用户名\项目` 或 `\\wsl$\发行版\路径`。

WSL 仓库的 Git、文件读写、冲突处理、Hook 和文件监听全部在所选发行版中执行；Windows 仓库继续使用 Windows Git。每个发行版需要安装可运行的 Git。Windows 安装包附带校验 SHA256 的 Linux Node 运行时，无须用户额外安装 Node，也不启动网络服务。运行时架构随安装包架构匹配，目标发行版需兼容官方 Node Linux 运行时（glibc）。开发模式可执行 `node -e "require('./scripts/prepare-wsl-runtime.cjs').prepareRuntime(process.cwd(),process.arch)"` 准备同一运行时，未准备时使用发行版 PATH 中的 Node。

WSL 核心通过受限的标准输入输出协议复用现有 Git 服务。Windows 主进程集中保存信任记录和活动日志；信任记录按发行版隔离，多浏览器会话共用保存队列，不修改 WSL 的全局 Git 配置。Linux 核心连接中断时不会自动重放写入操作。

最近仓库使用 `gitcode.recent`，首次启动会从旧 `gitk.recent` 读取迁移。若已有旧 Electron 用户配置目录且尚无 GitCode 配置，会继续使用旧目录，避免复制运行中的 Chromium 配置。旧 `GITK_GIT_PATH`、`GITK_DEV_URL`、`GITK_SOFTWARE_RENDERING` 仍作为兼容别名；新名称为 `GITCODE_GIT_PATH`、`GITCODE_DEV_URL`、`GITCODE_SOFTWARE_RENDERING`。`gitk` preload/IPC 标识保留为内部稳定协议，GitKraken 的引用名称保持不变。

### 操作反馈与确认方式

普通推送、拉取先核对当前分支、配置和远端状态，通过后直接执行。首次发布需要确认远端与目标分支；目标分叉、核对失败或需要补充输入时才显示顶部确认条。工具栏“同步选项”保留显式核对目标和仅快进拉取入口，右键对指定分支的操作仍展示目标确认。

获取远端更新使用独立按钮状态，可继续浏览缓存标签页；同仓库重复获取合并为一次请求。Git 核心仍串行执行，前台写操作不会与获取同时写入。结果绑定发起仓库，晚到的获取结果不会覆盖较新的仓库快照。检出等前台操作在命令与刷新都结束后才解除阻塞。

克隆提交参数后关闭表单，保留输入草稿，在提交图区下方展示独立进度。获取、推送、拉取使用相同进度组件；百分比来自 Git 当前阶段的输出，不代表整体完成比例。没有可用百分比时显示不定进度。取消后等待核心结束并重新读取状态，取消不承诺回滚已完成操作。

普通新建分支优先在 HEAD 的关系图单元格就地输入；HEAD 不在当前筛选结果中时，退回顶部表单。重命名、删除等简单确认条置于标题栏下方，保留取消、键盘与焦点保护；冲突和变基等复杂流程继续使用独立界面。

GitKraken 对照清单与证据见 `design/operation-feedback/index.html`。其中需要账号或特定网络环境的动态场景仍标记待验证，不作为已经实测的行为。

### 推送恢复与冲突面板

推送核对发现远端有未整合提交时，可选择“拉取并推送”。本机核心在同一次串行操作中核对当前分支与原推送目标，使用 Merge 获取并整合更新，成功后重新核对远端再推送。拉取上游与推送目标不同、首次发布、非当前分支、冲突、自动贮藏恢复失败、取消、配置改变或远端再次推进时停止，不会自动强推、循环合并或在稍后解决冲突时恢复旧的推送请求。拉取完成后出现额外提交也不会被自动带入续推。

普通合并和恢复修改的冲突显示在右侧面板，关系图与仓库导航可继续查看。点击冲突文件打开全工作区三方编辑器，上方显示当前/传入版本，下方编辑结果。保存仅标记该文件已解决；所有文件解决后点击“完成合并”，只创建本地合并提交，之后手动推送。恢复修改的冲突不提供合并提交或中止合并按钮，解决后回到普通工作区并保留贮藏记录。未保存的编辑草稿仍受切仓、关标签和退出保护。

实现与验收截图见 `design/sync-recovery/index.html`；GitKraken 实测证据仍保留在 `design/state-change-research/live/index.html`。

### Git 控制台

工具栏或“视图 → Git 控制台”可打开底部只读控制台，与交互式终端共用工具窗口。GUI Git 操作默认在内存中记录，面板隐藏时也继续记录；打开后按游标补齐，再以约 200 ms 的批次更新。后台状态、差异等读取不刷屏。命令、输出及结束状态以仓库、操作 ID 和命令 ID 隔离；Windows 的 WSL 仓库由对应发行版的核心记录。

“清空”只重置当前仓库的显示游标，隐藏不终止进程；取消沿用现有操作取消入口，等进程结束后才记录取消结果。GUI 写操作仍由现有 Git 队列串行执行，控制台读取不占队列。Shell 终端中的手动命令独立执行，不纳入 GUI 命令日志或队列。

控制台保留最多 2 MiB / 6000 条内存事件；界面每个仓库最多显示 1500 行 / 256 Ki 字符，保留最近 20 个仓库的显示状态，超出会提示省略。重启应用后不恢复控制台输出，持久记录仍在活动日志。输出经过凭据脱敏，提交说明和 stdin 不记入命令；不要用控制台作为保存敏感信息的渠道。

底部工具窗口以同一排标签呈现“Git 控制台”和“终端 1、终端 2…”；Git 控制台为固定标签，＋可从任意标签新建 Shell。标签切换和隐藏面板只改变显示，不终止 Shell。终端编号在当前仓库标签页内递增，关闭会话后不重排；关闭最后一个 Shell 回到 Git 控制台。各仓库标签页保留自己的选择。
